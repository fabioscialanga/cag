# Community

CAG is a preview project, so community channels should stay lightweight and focused.

## GitHub Discussions

Recommended setup:

- enable GitHub Discussions in repository settings
- create categories:
  - `Q&A` for setup and usage questions
  - `Show and tell` for demos, benchmarks, and integrations
  - `Ideas` for retrieval, Knowledge Compiler, and evaluation proposals
  - `Announcements` for releases and roadmap updates

Suggested first pinned post:

```text
Welcome to CAG Discussions.

Use Q&A for setup problems, Show and tell for demos or benchmark runs, and Ideas for proposals that are not yet concrete issues.

For bugs, security reports, and scoped feature requests, use Issues instead.
```

## Issues vs Discussions

Use Issues for:

- reproducible bugs
- failing commands
- benchmark regressions
- scoped feature requests
- documentation fixes

Use Discussions for:

- open-ended architecture questions
- implementation ideas that need shaping
- community examples
- benchmark result sharing
