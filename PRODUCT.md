# Product

## Register

product

## Users

AI builders, practitioners, and technical evaluators using CAG locally or in preview to test grounded document QA workflows. They are focused, skeptical, and often comparing orchestration quality against simpler RAG baselines, so they need fast access to documents, answers, evidence, confidence, risk, and graph traces.

## Product Purpose

CAG is a graph-driven retrieval reasoning workspace. The interface exists to make upload, ingestion, querying, evidence selection, validation, and escalation inspectable from one operational surface. Success means users can quickly load source material, ask grounded questions, verify why an answer was produced or refused, and trust the system's reasoning path without reading raw logs.

## Brand Personality

Precise, calm, technical. The product should feel like a serious control desk for evidence-aware AI systems, not a generic chat demo or decorative SaaS landing page.

## Anti-references

Avoid beige editorial styling, marketing-page hero language, oversized decorative cards, glassy AI-console cliches, neon dark-mode theatrics, and generic SaaS dashboard patterns that hide the retrieval and validation mechanics. The interface should not look like a toy RAG demo or a content marketing site.

## Design Principles

- Put evidence before ornament: the UI should foreground selected context, confidence, risk, sources, and graph state.
- Make the system's judgment inspectable: users should see when CAG is ready, uncertain, escalating, ingesting, or missing evidence.
- Preserve flow for repeated testing: upload, ask, inspect, reset, and rerun should stay close at hand.
- Earn trust through restraint: use a light professional interface with clear hierarchy, consistent controls, and minimal decorative styling.
- Support technical depth without clutter: dense diagnostic data is welcome when it is organized for scanning.

## Accessibility & Inclusion

Target WCAG AA contrast, visible focus states, keyboard-operable controls, readable type sizes, and reduced-motion-friendly transitions. Status, error, and risk information should not rely on color alone.
